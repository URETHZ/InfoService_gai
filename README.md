# АИС ГАИ (Автоматизированная Информационная Система ГАИ)

Курсовой проект по дисциплине «Базы данных». 
Десктопное приложение для комплексного учета деятельности городского отдела ГАИ/ГИБДД: регистрация транспортных средств, учет владельцев, фиксация ДТП, прохождение техосмотров и формирование аналитических отчетов.

## 📋 Основной функционал

* **Авторизация и безопасность:** Вход в систему с использованием хеширования паролей (Argon2id) и проверкой прав доступа (RBAC).
* **Динамическое меню:** Структура меню и права доступа (R/W/E/D) хранятся в БД и подгружаются динамически.
* **Модульный подход:** Бизнес-логика вынесена в отдельные динамические библиотеки (DLL), загружаемые «на лету».
* **Учет ТС и владельцев:** Ведение картотеки автомобилей (легковых, грузовых, мотоциклов) и их привязка к физическим/юридическим лицам.
* **Учет ДТП:** Регистрация происшествий, фиксация участников и степени тяжести.
* **Техосмотры:** Учет прохождения ТО, расчет оплаты и проверка периодичности.
* **Аналитика и отчеты:** Построение графиков и дашбордов (Qt Charts), выгрузка отчетов в MS Word и MS Excel.

## 🛠 Технологический стек

* **Язык программирования:** C++ (стандарт C++17)
* **Фреймворк:** Qt 6 (Qt Quick / QML, Qt SQL, Qt Concurrent)
* **СУБД:** PostgreSQL (драйвер QPSQL)
* **Система сборки:** CMake
* **Библиотека хеширования:** Argon2 (официальная реализация на C)

## 🏛 Архитектура приложения

Приложение построено по модульному принципу (Main Executable + Dynamic Libraries).
* **Главный EXE:** Отвечает за жизненный цикл приложения, авторизацию, построение меню и подгрузку DLL.
* **Модули (DLL):** Содержат бизнес-логику работы с конкретными сущностями. Связывание происходит **явно** (Explicit Linking) с помощью класса `QLibrary` в момент выбора пункта меню.
* **Паттерн MVVM:** Интерфейс (QML) полностью отделен от данных (C++). Взаимодействие происходит через `Q_PROPERTY`, `Q_INVOKABLE` методы и сигналы/слоты.
* **Многопоточность:** Для предотвращения зависания UI тяжелые SQL-запросы выполняются в фоновом потоке (паттерн *Worker Object* с использованием `QThread` и `moveToThread`).

## 🗄 Структура базы данных

База данных разделена на две логические схемы:
1. **`SystemVal` (Служебная схема):** 
   * `users` — список пользователей (пароли хранятся в виде хеша `соль:хеш`).
   * `menu` — иерархическая структура меню.
   * `rights` — матрица прав доступа (R/W/E/D) пользователей к пунктам меню.
2. **`public` (Предметная область):** 
   * Таблицы для учета ТС (`car`), владельцев (`owner_physical`, `owner_legal`), ДТП (`dtp`), техосмотров (`tech_inspection`) и различных справочников (марки, модели, улицы).

## 🔐 Безопасность и надежность

* **Хеширование паролей:** Используется современный алгоритм **Argon2id** с уникальной случайной солью для каждого пользователя (защита от Rainbow Table атак).
* **Контроль доступа:** Права проверяются как на уровне отрисовки интерфейса в QML, так и на уровне выполнения SQL-запросов в C++.
* **Потокобезопасность БД:** Класс `DataBaseController` (реализованный как Singleton) автоматически создает отдельное соединение с PostgreSQL для каждого потока (на основе `QThread::currentThread()`), что исключает состояние гонки (race condition).
* **Защита от SQL-инъекций:** Все параметры передаются в запросы через `bindValue()` (Prepared Statements).
